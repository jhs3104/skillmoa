# ADR-0023: 새 저장소는 스타순 저장소 검색으로 찾는다

- 상태: 채택
- 날짜: 2026-11-09

## 맥락

11월 5일 뒤로 저장소가 1,300개 근처에서 늘지 않았다. 발견 소스는 토픽 5개와 awesome 리스트뿐이었고, 토픽을 달지 않은 저장소는 코드 검색으로만 찾게 되어 있었다. 코드 검색은 SKILL.md 7,225,344개를 상대로는 성립하지 않아 예약 실행에서 껐다 (ADR-0013 2026-11-09 추가 결정).

사이트는 스타순 상위 19,000개, 저장소당 10개까지만 싣는다 (ADR-0011, ADR-0003). 그렇다면 GitHub의 모든 스킬을 훑을 필요가 없다. 스타가 많은 스킬 저장소부터 빠짐없이 찾으면 된다. 저장소 검색은 스타 조건(`stars:`)과 스타순 정렬을 지원하고, 결과에 스타 수와 `pushed_at`이 함께 온다.

2026-11-09 실측:

| 스타 기준 | `skill in:name,description,topics` 결과 | 그중 알려지지 않은 저장소 |
|---|---|---|
| 1,000 이상 | 841 | 587 |
| 100 이상 | 4,793 | 4,313 |
| 10 이상 | 22,661 | 21,893 |

끝까지 읽는 데 15.5분 걸렸다. 상위권 샘플은 대부분 실제 스킬 저장소였다. "skill"은 "skills"도 찾는다.

## 결정

- 매 실행(`daily`)에서 `[discovery] repository_queries`를 스타 10개 이상까지 스타순으로 읽는다.
- 검색은 쿼리당 1,000건까지만 돌려준다. 스타 내림차순으로 1,000건을 읽고, 마지막으로 본 스타 수를 다음 창의 상한(`stars:10..N`)으로 삼는다. 같은 스타 수가 1,000개 넘게 몰려 상한이 줄지 않으면 한 칸 내린다. 그 스타 수의 일부를 놓칠 수 있지만 무한 반복하지 않는다.
- 실행당 30분(`repository_search_minutes`)까지 읽는다. 넘기면 스타가 적은 쪽 끝만 이번 실행에서 빠지고, 위쪽은 다음 실행이 다시 읽는다. 실행은 멈추지 않는다.
- 발견을 갱신보다 먼저 한다. 검색 결과로 최신 메타데이터를 받은 저장소는 갱신 호출을 건너뛴다. 저장소마다 한 번씩 부르는 갱신은 저장소가 2만 개가 되면 시간당 5,000회 한도를 넘기 때문이다. 검색에 잡히지 않은 저장소(스타 10개 미만 토픽 저장소, 큐레이션)만 따로 갱신한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 코드 검색 전수 조회 | 스타순 정렬이 없어 상위를 고르려면 전부 읽어야 한다. 쉬지 않고 약 5일이 걸린다 |
| 토픽을 더 늘린다 | 토픽을 다는 저장소만 잡힌다. 상위권 샘플의 64%가 우리가 몰랐던 저장소였다 |
| `SKILL.md in:readme` | 스타 10개 이상 55,062개로 넓지만 README에 SKILL.md를 언급만 한 저장소가 섞인다 |
| 저장소 메타데이터를 GraphQL로 묶어 갱신 | 호출은 줄지만 검색 결과로 이미 최신값을 받으므로 지금은 필요 없다 |

## 결과

- 첫 며칠은 새 저장소 약 2만 2천 개를 스캔한다. 저장소마다 트리 호출 한 번이라 시간당 5,000회 한도에 걸리고, 스캔 예산(120분)과 실행 마감(ADR-0013) 안에서 스타순으로 나눠 처리한다.
- 요약 대상은 순위 상위 19,000개뿐이라 요약 비용은 상한 계획(ADR-0011, ADR-0013) 안에 있다. 스타가 더 많은 새 스킬이 들어오면 기존 스킬 일부가 목록에서 밀린다.
- 중국어·일본어 본문 저장소가 많이 잡힌다. 스캔 뒤 언어 필터(ADR-0017)가 거른다.
