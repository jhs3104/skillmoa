# ADR-0011: 사이트에 싣는 스킬 수에 상한을 둔다

- 상태: 채택
- 날짜: 2026-11-02

## 맥락

`catalog_limit`은 첫 실행에만 쓰였다. 이후 매일 실행은 찾은 스킬을 순위대로 하루 호출 상한까지 계속 요약했고, 요약된 스킬은 모두 사이트에 실렸다. 지금 목록은 모든 행을 HTML에 담으므로(ADR-0008), 아무 결정 없이도 몇 주 뒤 홈이 수 MB로 커질 수 있었다. GitHub의 `SKILL.md`는 코드 검색 기준 약 680만 개라 후보가 부족할 일은 없다.

## 결정

- `catalog_limit`을 첫 실행과 매일 실행에 똑같이 적용한다. 상한 밖 스킬은 요약하지 않고 내보내지도 않는다.
- 상한은 19,000개다. 한 번 실행에 최대 1,000개, 하루 최대 8,000개를 요약한다.
- 설정값의 최댓값은 19,000이다. Cloudflare 무료 플랜의 정적 파일 2만 개 제한에서 상세 외 파일을 위한 여유를 남긴 값이고, 넘으면 설정을 읽을 때 실패한다.
- 목록은 필요할 때 불러오는 구조로 바꾼 뒤 상한을 올렸다 (ADR-0012).

## 검토한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| 300개로 시작 | 가장 안전하다 | 다른 디렉터리보다 지나치게 적다 |
| 처음부터 19,000개 | 한 번에 규모를 갖춘다 | 지금 목록 구조로는 쓸 수 없고 품질을 먼저 측정해야 한다 |
| 상한 없이 매일 늘림 | 설정이 필요 없다 | 사이트 크기와 비용이 눈에 띄지 않게 커진다 |
| 2만 개까지 허용 | 숫자가 깔끔하다 | 상세 페이지 외 파일까지 합치면 제한을 넘는다 |

## 결과

- 상한에 닿으면 순위가 높은 새 스킬이 낮은 스킬을 밀어낸다. 밀려난 스킬의 상세 페이지는 사라질 수 있다.
- 저장소당 10개 상한이 모든 실행에 적용된다.
- 2만 개 넘게 다루려면 D1과 온디맨드 렌더링이 필요하다.
