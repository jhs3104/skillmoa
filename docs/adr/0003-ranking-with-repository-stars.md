# ADR-0003: 저장소 단위 스타는 저장소 내 감쇠와 상한으로 스킬 순위에 반영한다

- 상태: 채택
- 날짜: 2026-11-01

## 맥락

GitHub 스타는 스킬이 아니라 저장소에 붙는다. 한 저장소에 스킬이 수백 개 있으면, 스타 순 정렬에서 상위가 그 저장소의 스킬로 채워지고 나머지가 밀려난다. 스킬별 인기 지표는 공개되어 있지 않다.

## 결정

저장소 안의 스킬을 경로가 얕은 순서, 경로 이름순으로 나열한 뒤 k번째(1부터) 스킬의 유효 점수를 다음과 같이 계산한다.

```
effective_stars = stars × 0.7^(k-1)
```

- 전체 스킬을 유효 점수 내림차순, 동률이면 식별자 오름차순으로 정렬해 `rank`를 매긴다.
- 첫 출시 300개를 고를 때는 저장소당 10개 상한을 추가로 건다.
- 감쇠율과 상한은 코드가 아니라 설정값으로 둔다.
- 사이트의 기본 정렬은 `rank`를 쓰고, 화면의 스타 수는 "저장소 스타"임을 명시한다.

## 검토한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| 스타 그대로 정렬 | 설명이 쉽다 | 대형 모음 저장소가 상위를 독점한다 |
| 상한만 적용 | 구현이 단순하다 | 11번째 스킬이 순위에서 갑자기 사라지고, 상한 안의 스킬은 모두 같은 점수로 뭉친다 |
| 스타를 스킬 수로 나눔 | 저장소별 총점이 공평하다 | 잘 관리되는 큰 모음의 대표 스킬까지 함께 낮아진다 |
| 설치 수 등 외부 지표 | 스킬 단위로 측정된다 | 안정적인 공개 출처가 없다 |

## 결과

- 저장소당 앞쪽 스킬이 대표로 올라오고, 뒤쪽 스킬은 다른 저장소와 섞인다.
- 저장소 내 순서는 인기가 아니라 경로 기준이다. 대표성을 보장하지는 않는다.
- 같은 입력에서 항상 같은 순위가 나온다.
- 스킬 단위 지표가 생기면 이 식을 교체한다. 사이트는 `rank`만 읽으므로 영향이 없다.
