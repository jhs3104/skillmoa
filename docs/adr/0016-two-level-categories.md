# ADR-0016: 카테고리를 대분류 13개와 세부 분류 60개의 2단계로 나눈다

- 상태: 채택
- 날짜: 2026-11-03

## 맥락

카테고리가 13개뿐이고 정의도 없어서 경계에 있는 스킬이 그때그때 다르게 분류되었다. 첫 970개 중 `ai-agents`가 24%를 차지해 어디에도 안 맞는 스킬을 담는 통이 되었다. 참고 사이트(claudeskills.info)는 61개 카테고리를 한 줄에 나열하지만, 하는 일, 업종, 매체, 프로그래밍 언어가 한 목록에 섞여 있다.

이 사이트는 대분류마다 색 하나를 주는 색 라벨 체계를 쓴다(ADR-0009). 색으로 61개를 구분할 수는 없다.

## 결정

- 대분류 13개와 색 라벨은 그대로 둔다. 그 아래에 세부 분류 60개를 둔다. 예: 개발 › 프론트엔드·백엔드·모바일·Git.
- 모델은 세부 분류 하나만 고른다. 대분류는 코드가 `SUBCATEGORY_PARENT`로 정하므로 둘이 어긋날 수 없다.
- 기준은 사용자가 이 스킬로 끝내는 일이다. 프로그래밍 언어는 분류가 아니라 검색으로 찾는다.
- 대분류와 세부 분류의 관계는 `collector/src/collector/domain/models.py`가 원본이다. collector가 `site/src/data/taxonomy.json`을 생성하고, 양쪽 테스트가 프롬프트, 사이트 표시 이름과 어긋나지 않는지 확인한다.
- 목록에서는 대분류를 고르면 그 아래 세부 분류 칩 줄이 열린다. 세부 분류가 둘 이상인 대분류만 칩 줄을 둔다. URL은 `?category=development&sub=frontend`이다.
- 목록 행과 상세 머리에 세부 분류 이름을 글자로 보인다. 색은 대분류만 쓴다.
- 프롬프트 v6에 넣는다. v5 이전 요약은 세부 분류가 비어 있고, 사이트는 비어 있으면 표시하지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 평면으로 40~60개 | 색 라벨 체계가 무너지고 모바일 필터 시트가 길어진다 |
| 13개 유지 | 수천 개가 쌓인 뒤 세분화하면 재요약 비용이 그만큼 커진다 |
| 대분류와 세부 분류를 모델이 따로 고름 | 서로 어긋난 조합이 생긴다 |

## 결과

- 기존 970개는 `refresh_prompt` 실행 한 번(약 $1.6)으로 세부 분류를 얻는다.
- 세부 분류 페이지(`/category/frontend/` 같은 검색 유입 페이지)는 스킬이 충분히 쌓인 뒤 따로 정한다.
