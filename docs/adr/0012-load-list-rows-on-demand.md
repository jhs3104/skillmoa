# ADR-0012: 목록 행을 필요할 때 불러와 그린다

- 상태: 채택
- 날짜: 2026-11-02
- ADR-0008을 대체한다.

## 맥락

ADR-0008은 모든 행을 HTML에 담고 숨겨 두었다. 300개에는 맞았지만, 상한을 올리면 홈이 1만 개에서 약 14MB가 된다. AI 찾기와 맞춤 추천 페이지도 전체 행을 템플릿으로 담고 있었다. AI 찾기 Worker는 전체 목록을 읽어 잘랐는데, 목록이 커지면 무료 플랜의 CPU 제한에 걸릴 수 있었다.

## 결정

- HTML에는 처음 50행만 넣는다. 나머지는 `/catalog.json`을 받아 브라우저에서 그린다.
- 행 마크업의 원본은 `lib/skill-row.ts` 하나다. 서버 출력, 목록, AI 찾기, 맞춤 추천이 모두 쓴다.
- 데이터는 페이지가 한가할 때 미리 받는다. 데이터 절약 모드에서는 필요할 때만 받는다.
- 검색, 필터, 정렬, 더 보기를 쓸 때까지 받지 못했으면 불러오는 중으로 표시하고, 실패하면 다시 시도할 수 있게 한다.
- 펼친 개수와 스크롤 위치는 `history.state`에 보관한다.
- AI 찾기는 상위 300개만 담은 `/catalog-ai.json`을 읽는다.

## 검토한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| 페이지 번호로 정적 생성 | 데이터 전송이 없다 | 브라우저 안 검색이 전체를 찾지 못한다 |
| D1과 검색 API | 수만 개 이상도 다룬다 | 서버 없음 원칙에 어긋나고 이 규모에는 과하다 |
| 목록 데이터를 조각으로 분할 | 첫 전송이 작다 | 검색에는 결국 전체가 필요하다 |
| 행 템플릿을 HTML에 두고 복제 | 마크업이 Astro에 남는다 | 데이터 칸을 채우는 코드가 따로 생긴다 |

## 결과

- 가짜 1만 개 기준 홈 HTML은 79KB(압축 8KB), 빌드는 40초, 4배 느린 CPU에서 검색은 약 0.13초였다. 반복 문구라 실제 압축 크기는 더 크다.
- `/catalog.json`은 1만 개에서 약 7.7MB다. 실제 압축 크기는 운영 데이터로 다시 재야 한다.
- 자바스크립트가 없으면 처음 50행만 보인다. 나머지 스킬은 사이트맵으로 찾을 수 있다.
- 상세 페이지를 스킬마다 만들므로 상한은 여전히 ADR-0011을 따른다.
