# ADR-0004: 자연어 추천은 전체 목록을 Claude에 넘기고, KV로 비용을 묶는다

- 상태: 채택
- 날짜: 2026-11-01

## 맥락

질문 몇 개로는 표현하기 어려운 요구를 문장으로 받고 싶다. 개인 프로젝트라 공개 API의 비용이 통제되지 않으면 곤란하고, Workers KV 무료 쓰기는 하루 1,000건이다. 카탈로그는 첫 출시 기준 300개다.

## 결정

- MVP는 스킬 이름과 한 줄 요약 목록을 질문과 함께 Claude API에 넘겨 추천과 이유를 받는다.
- 추천은 `Recommender` 인터페이스 뒤에 둔다. 임베딩 검색으로 바꿀 때는 구현만 교체한다.
- 질문은 정규화한 뒤 SHA-256 키로 KV에 7일간 캐시한다. 표기만 다른 같은 질문은 한 번만 호출한다.
- IP당 하루 5회, 전체 하루 300회로 제한한다. 호출 1회에 KV 쓰기가 3번이므로 전체 쓰기는 900회 이하다.
- 캐시 적중은 Claude를 부르지 않으므로 한도를 차감하지 않는다.
- IP는 날짜를 섞어 해시한 값만 저장한다.
- 모델이 돌려준 슬러그는 목록과 대조하고, 없는 스킬은 버린다.
- 다른 출처의 요청은 `Origin` 검사로 거부한다.

## 검토한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| Workers AI 임베딩 + Vectorize | 호출당 비용이 낮고 카탈로그가 커져도 입력이 늘지 않는다 | 300개 규모에는 과하다. 카탈로그가 커지면 이 방식으로 옮긴다 |
| Durable Objects로 정확한 카운터 | 동시 요청에도 정확하다 | 개인 프로젝트의 한도 관리에는 과하다 |
| 브라우저에서 키워드 검색만 제공 | 비용이 없다 | 문장으로 표현한 의도를 다루지 못한다 |

## 결과

- KV는 최종 일관성이고 읽고 쓰는 사이에 원자성이 없어서, 동시 요청이 몰리면 한도를 조금 넘을 수 있다. 비용 상한으로는 충분하다고 판단했다.
- 카탈로그가 커질수록 입력 토큰이 늘어난다. 그래서 입력은 순위 상위 300개로 자른다.
- 카탈로그는 Worker 번들에 넣지 않고 정적 자산 `/catalog.json`을 `ASSETS` 바인딩으로 읽는다.
