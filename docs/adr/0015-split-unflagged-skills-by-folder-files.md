# ADR-0015: 표시가 없는 스킬은 폴더의 파일로 한 번 더 나눈다

- 상태: 채택
- 날짜: 2026-11-03
- ADR-0010을 보완한다.

## 맥락

첫 수집 970개 중 157개는 AI가 SKILL.md에서 코드 실행도 네트워크 접속도 찾지 못해 `코드·네트워크 미확인`으로 표시되었다. 사용자는 이것을 분류에 실패한 스킬로 읽었다. 실제로는 대부분 글쓰기 지침이나 점검 목록처럼 실행할 것이 없는 스킬이다. 그렇다고 AI 판단만으로 "없음"이라고 쓸 수는 없다. AI는 SKILL.md만 읽고, 함께 든 파일의 내용은 읽지 않기 때문이다.

수집 단계는 스킬 폴더의 파일 목록을 이미 가지고 있다. 이 목록은 AI 판단이 아니라 확인할 수 있는 사실이다.

## 결정

- export에 `scriptFiles`를 넣는다. 값은 `none`, `present`, `unknown`이다.
  - 스크립트 확장자(.py, .sh, .js 등)이거나 `scripts/`, `bin/` 아래에 있는 파일이 하나라도 있으면 `present`
  - 저장소 루트의 스킬이거나 파일 목록이 30개 상한에서 잘렸으면 `unknown`
  - 나머지는 `none`
- AI가 코드 실행과 네트워크를 둘 다 찾지 못한 스킬만 이 값으로 표시를 바꾼다.
  - `none`: `지침 문서만` (보조 글자)
  - `present`: `스크립트 포함` (주의 배지). AI는 실행 지시를 못 찾았지만 실행할 파일이 들어 있다.
  - `unknown`: 기존대로 `코드·네트워크 미확인`
- 상세의 GitHub 기록에 `스크립트 파일` 줄을 둔다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 카테고리를 더 잘게 나누기 | 카테고리는 용도이고, 이 표시는 설치 전 위험이다. 섞으면 둘 다 흐려진다 |
| AI에게 "실행 없음"을 판단시키기 | 없다는 판단은 검증할 근거 문장이 없다. ADR-0010의 근거 원칙과 맞지 않는다 |
| 표시를 아예 지우기 | 표시가 없으면 안전하다는 뜻으로 읽힌다 |

## 결과

- 157개가 `지침 문서만` 141개, `스크립트 포함` 10개, `미확인` 6개로 나뉜다.
- `스크립트 포함`은 AI가 놓쳤을 수 있는 실행을 드러낸다. 예: obra/superpowers의 brainstorming.
- `지침 문서만`도 안전 보증은 아니다. 에이전트가 지침을 따르며 스스로 명령을 실행할 수 있다. 문구는 사실(파일 구성)만 말한다.
