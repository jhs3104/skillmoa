# ADR-0014: 목록은 더 보기 대신 쪽 번호로 넘긴다

- 상태: 채택
- 날짜: 2026-11-03
- ADR-0012의 "더 보기"와 "펼친 개수 보관"을 대체한다. 데이터를 필요할 때 받는 방식은 그대로다.

## 맥락

첫 수집으로 목록이 970개가 되었고 7천 개 이상으로 늘어난다. 더 보기는 50행씩 이어 붙이므로 몇 번 누르면 스크롤이 길어지고, 푸터와 필터로 돌아가기 어렵다. 지금 몇 번째쯤을 보고 있는지도 알 수 없고, 보던 위치를 링크로 공유할 수 없다. 이 목록은 순위형 디렉터리라서 "몇 위쯤"이라는 위치가 의미가 있다.

## 결정

- 한 쪽에 50행을 보여 주고, 목록 아래에 `이전 1 2 3 4 5 … 20 다음`을 둔다.
- 쪽 번호는 처음, 끝, 현재 주변만 보여 준다. 칸 수가 늘 7개라서 쪽을 옮겨도 버튼 위치가 흔들리지 않는다.
- 480px 미만에서는 번호 대신 `이전 3 / 20 다음`만 둔다.
- 쪽 번호는 URL의 `page`에 둔다. 쪽을 옮기면 기록을 남겨 뒤로 가기로 이전 쪽에 돌아간다. 검색, 필터, 정렬을 바꾸면 1쪽으로 돌아가고 기록은 바꿔 쓴다.
- 쪽을 옮기면 목록 머리로 스크롤하고 첫 행으로 초점을 옮긴다.
- 상세에서 돌아오면 같은 쪽과 스크롤 위치로 돌아간다.
- 범위를 벗어난 쪽 번호는 마지막 쪽으로 맞춘다.
- 쪽 번호 마크업은 `lib/browse.ts`의 `pagerHtml` 하나로 서버와 브라우저가 함께 쓴다.

## 검토한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| 더 보기 유지 | 모바일에서 손가락 이동이 적다 | 위치를 알 수 없고 길어진 목록에서 푸터·필터로 돌아가기 어렵다 |
| 무한 스크롤 | 조작이 없다 | 푸터에 닿을 수 없고 키보드 사용자가 불리하다 |
| 쪽마다 정적 HTML 생성 | 자바스크립트 없이 동작한다 | 검색·필터 결과에는 쓸 수 없고 정적 파일 수 제한을 쓴다 |

## 결과

- 2쪽 이후는 목록 데이터를 받은 뒤에 그린다. 자바스크립트가 없으면 1쪽만 보이고 쪽 번호는 숨긴다.
- 2쪽 이후 URL은 검색 엔진 색인 대상이 아니다. 개별 스킬은 상세 페이지와 사이트맵으로 색인된다.
