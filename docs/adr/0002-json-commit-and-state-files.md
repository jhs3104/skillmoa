# ADR-0002: 결과와 수집 상태를 JSON으로 Git에 커밋한다

- 상태: 채택
- 날짜: 2026-11-01

## 맥락

GitHub Actions 러너는 실행마다 초기화된다. 증분 수집과 비용 통제에는 어떤 저장소를 언제까지 봤는지, 어떤 SKILL.md를 어떤 프롬프트로 요약했는지를 다음 실행으로 넘길 저장소가 필요하다. ADR-0001에 따라 서버와 DB는 두지 않는다.

## 결정

- `collector/state/`에 수집 상태를, `site/src/data/skills.json`에 사이트 데이터를 저장하고 같은 커밋으로 남긴다.
- 상태는 변경 주기에 따라 파일을 나눈다.
  - `meta.json`: 스키마 버전, 최초 수집일, 일일 호출량
  - `repositories.json`: 저장소 사실과 스캔 위치. 스타 때문에 자주 바뀐다
  - `skills.json`: 스킬 경로와 해시
  - `summaries.json`: 요약과 실패 기록. 가장 드물게 바뀌고 다시 만들 때 돈이 든다
- 모든 JSON은 키를 정렬하고 들여쓰기해서 쓴다. 쓰기는 임시 파일 후 교체로 처리한다.
- SKILL.md 해시는 git tree의 blob SHA를 그대로 쓴다. 본문을 받지 않고도 변경과 완전 중복을 판단할 수 있다.
- 재개는 별도 체크포인트 없이 상태로 처리한다. 저장소마다 `scanned_pushed_at`을 기록하고, 요약은 해시가 같으면 건너뛴다. 프롬프트를 바꿨을 때의 전체 재요약은 비용이 들어 `--refresh-prompt`로 명시할 때만 한다.
- 같은 입력에는 같은 출력을 낸다. 실행 시각은 `skills.json`에 넣지 않고, 실행 지표는 커밋하지 않는 `collector/build/`와 Actions 아티팩트로 남긴다.

### `lastSeenAt`을 스캔 시점에만 갱신한다

실행할 때마다 모든 스킬의 `last_seen_at`을 갱신하면 데이터가 그대로여도 매일 전체 파일이 바뀐다. 그래서 날짜 단위로만 기록하고, 실제로 tree를 스캔한 저장소의 스킬만 갱신한다. `skills.json`에는 내보내지 않는다.

### 최초 수집을 "새 스킬"에서 제외한다

첫 실행에서는 모든 스킬의 `firstSeenAt`이 같은 날이 되어 300개 전부 "새로 나온 스킬"로 보인다. `bootstrappedOn`을 내보내고 그날 발견된 스킬은 신규 목록에서 뺀다.

## 검토한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| D1/KV에 상태 저장 | 커밋 이력이 깨끗하다 | 배치가 Cloudflare API에 의존하고, 데이터 변경 이력을 리뷰할 수 없다 |
| Actions 캐시 | 커밋이 필요 없다 | 캐시는 만료되며 유일한 사본이 될 수 없다 |
| 파일 하나로 통합 | 구현이 단순하다 | 스타 변경과 요약 변경이 한 파일에 섞여 diff가 커진다 |

## 결과

- 데이터 변경이 PR과 커밋으로 추적되고, 배포된 데이터는 항상 특정 커밋으로 재현된다.
- 카탈로그가 커지면 저장소 크기와 파일 크기가 문제가 된다. GitHub는 100MB가 넘는 파일을 거부하므로, 파일이 50MB에 가까워지면 샤딩하거나 D1로 옮긴다.
- 커밋을 만드는 주체가 Actions뿐이어야 충돌이 없다. 워크플로에는 `concurrency`를 건다.
