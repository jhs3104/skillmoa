# ADR-0018: 세부 분류는 요약과 따로 정한다

- 상태: 채택
- 날짜: 2026-11-04
- ADR-0016을 보완한다.

## 맥락

v6 요약 978개를 검수했더니 한국어 품질은 목표 안에 들어왔지만 분류는 약 9%(89개)가 틀렸다. 같은 실수가 반복됐다. 영상·오디오가 문서로, 브라우저 자동화와 프롬프트 작성이 에이전트 운영으로, 게임 개발이 개발 도구로 갔다.

요약과 분류를 한 호출로 만들면 분류 기준을 고칠 때마다 요약까지 다시 만들어야 한다. 3시간마다 1,000개씩 쌓이는 구조에서는 기준을 늦게 고칠수록 비용이 커진다.

## 결정

- 요약이 끝난 뒤, 요약문(소개, 이럴 때, 용도 태그)만 읽고 세부 분류 하나를 고르는 호출을 따로 둔다. 원문은 보내지 않아 호출이 작다.
- 분류 프롬프트는 `taxonomy_version`(`t1`부터)으로 관리한다. 기준을 바꾸면 버전만 올리고, 다음 실행이 요약은 그대로 둔 채 분류만 다시 정한다.
- 분류 기록에는 어떤 요약(해시, 프롬프트 버전)과 어떤 기준으로 정했는지 남긴다. 요약이 바뀌면 다시 분류한다.
- 사이트는 지금 요약을 보고 정한 분류가 있으면 그것을 쓰고, 없으면 요약이 고른 분류를 쓴다. 분류가 실패해도 목록이 비지 않는다.
- 모델은 Haiku로 시작한다. 검수에서 부족하면 `[classify] model`만 바꾼다.
- 하루·실행당 호출 상한을 요약과 따로 둔다.
- `t1`은 v6 설명에 검수에서 반복된 오분류를 막는 설명과 대조 규칙을 더했다.
- 기록에 남은 프롬프트(v1~v6)는 내용이 바뀌지 않도록 테스트로 고정한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| v7 요약 프롬프트로 함께 고치기 | 기준을 바꿀 때마다 쌓인 요약 전체를 다시 만들어야 한다 |
| 분류를 Sonnet으로 | 1,000개에 약 $3로 Haiku의 약 15배다. Haiku로 부족한지 먼저 본다 |
| 규칙(키워드)으로 분류 | 60개 세부 분류의 경계를 키워드로 나누기 어렵다 |

## 결과

- 분류 비용은 1,000개에 약 $0.2~0.4로 예상한다. 기준을 바꿔 전체를 다시 분류해도 같은 수준이다.
- 요약 프롬프트 안의 분류 지시는 남겨 둔다. 분류 호출이 실패했을 때 쓰는 값이다.
